# Security Policy — LocalReviewer

LocalReviewer — **local-first** инструмент одного AI-тренера. Он работает
**без интернета**: импорт, ревью, датасеты, прогоны, регрессия, баги,
отчёты, история и экспорт не делают сетевых вызовов.

## Что считается чувствительным

- Тексты кейсов (запрос клиента, ответ модели, эталон, комментарий).
- Содержимое Bug Report и экспортов.
- Персональные данные внутри кейсов: телефоны, email, URL, токены.

## Правила

1. **Не публикуй** реальные клиентские данные, рабочие API-ключи,
   production credentials и внутренние закрытые документы — ни в репозиторий,
   ни в issue, ни в логи.
2. В обычные логи пишется только техническое: ID кейса, тип операции,
   счётчики, длительность, ошибка, сервис, номер миграции. Содержимое
   кейсов — только при явно включённом диагностическом режиме
   («Настройки → Приватность»), который после отладки надо выключить.
3. Перед экспортом результатов/JSONL приложение показывает Privacy Scan
   (возможные телефоны/email/URL/токены — формулировки «возможный», без
   утверждений) и три выбора: **как есть / обезличенный / отмена**.
   Обезличенный пишет только копию в файл (`<EMAIL_1>`, `<PHONE_1>`,
   `<URL_1>`, `<SECRET_1>`), база не меняется. PERSON не обезличиваем
   (без NER — ложные срабатывания).
4. Буфер обмена после копирования может автоматически очищаться
   («Настройки → Приватность»). Очищается только наше содержимое
   (по fingerprint); чужой текст, скопированный поверх, не трогаем.
5. Проверка секретов в репозитории: `python tools/check_secrets.py`
   (и тот же шаг в CI). Тестовые фикстуры (`example.com`, номера `900`,
   `test`/`fake`/`dummy`) — в allowlist скрипта, реальные секреты —
   никогда в репо.

## Как сообщить об уязвимости

Открой issue в репозитории **без** чувствительных данных и секретов
(только описание, шаги, версия). Секреты и клиентские данные не прикладывать.
