# 📖 Руководство пользователя LocalReviewer

Подробная инструкция по всем возможностям программы. Краткий обзор — в [README](../README.md).

**Принцип программы:** человек принимает экспертное решение, программа убирает рутину вокруг него. Ничего не размечается автоматически — автопроверки, похожие кейсы и очередь только подсказывают.

## 1. Установка и запуск

**Готовая сборка (проще всего):** скачай `LocalReviewer-win64.zip` из раздела Releases на GitHub, распакуй, запусти `LocalReviewer.exe`. Установка, интернет и регистрация не нужны.

**Из исходников:** нужен Python 3.11+ и Windows 10/11.

```bash
git clone https://github.com/Rhun96/LocalReviewer.git
cd LocalReviewer
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Для `.ods` дополнительно нужен `odfpy` (уже есть в `requirements.txt`).

## 2. Проекты

Проект — это папка на диске. Всё (база, бэкапы, логи) хранится внутри неё, исходные файлы не изменяются никогда.

- **Создать проект** — выбери пустую папку, программа инициализирует базу.
- **Открыть проект** — выбери папку с `project.sqlite`. Старые проекты мигрируются автоматически (перед миграцией — автобэкап в `backups/`).

На экране проекта: список файлов, общий прогресс, кнопки перехода (Ревью, Прогоны, Датасеты, Отчёты, История, Бэкапы, Настройки).

Кнопка «🧹 Целостность» — проверка сирот (кейсы удалённых файлов: невидимы, но занимают место) с выборочной чисткой. Снимки версий при чистке не страдают.

## 3. Импорт файлов

Кнопка «Добавить файл» на экране проекта. Поддерживаются **.xlsx, .ods, .csv, .json, .jsonl** (`.xls` — нет, сохрани как `.xlsx`).

**Шаг 1 — файл.** Для Excel/ODS выбери лист, для CSV — кодировку и разделитель. Есть строка заголовка (0 = первая). Превью показывает первые строки.

**Шаг 2 — маппинг.** Каждой колонке назначается роль:

| Роль | Что значит |
|---|---|
| Запрос | главный текст кейса (обязательно!) |
| Ответ модели | ответ для проверки |
| Номер обращения | служебный номер (в метаданные) |
| Продукт | продукт (в метаданные, используется шаблонами) |
| Ответ оператора | эталон/ответ человека (в метаданные) |
| Группа / категория | группа (поле кейса) |
| **Идентификатор** | стабильный ID кейса — **главный ключ**: сравнение версий датасетов, сопоставление прогонов идут по нему |
| Комментарий из источника | подтянется как исходный комментарий |
| Источник (ссылка на БЗ) | показывается в кейсе как 🔗 |
| Дополнительное поле | в метаданные |
| Своя категория («＋ Своя категория…») | своё поле в метаданные, становится столбцом таблицы |

Свои категории хранятся в проекте (видны и в импорте прогонов), удаляются кнопкой «－ Категория»; при добавлении/удалении уже назначенные роли не слетают.
| Не импортировать | пропустить колонку |

Правила: «Запрос» обязателен; «Идентификатор» — только одна колонка; остальные роли можно назначать нескольким колонкам (тексты объединятся). У каждой колонки видны примеры значений (`↳ ...`) — сразу видно, где ID, а где пусто.

**Предимпортная проверка.** Перед импортом программа показывает: число строк, покрытие ID («ID заполнен: K из N»), дубли ID, пустые запросы. При проблемах — кнопки Продолжить/Остановить. Уже импортированный файл опознаётся при попытке импорта (по хэшу или имени) — повтор спросит отдельно. Дубли ID не запрещены, но в датасетах попадут в «конфликты», а сопоставление по ним ненадёжно — лучше починить файл.

**Импорт идёт в фоне** с прогрессом и «Отменой» (при отмене частичные данные сохраняются). Внутри файла дубли по содержимому пропускаются автоматически.

## 4. Ревью: режимы и навигация

Два вида, переключатель «📋 Таблица / 📝 Кейс»:

- **Кейс** — один кейс на экране: запрос, ответ, источник, автопроверки, статусы, комментарий, теги. Листание стрелками ←/→ или кнопками.
- **Таблица** — пагинация по 50, выбор столбцов («📊 Столбцы»), фильтр по значениям столбца, колонка ⚠ (сводка автопроверок: 🔴 error, 🟡 warning, 🔵 info), сортировка (порядок импорта / сначала непроверенные / сначала проблемные).

Шапка кейса: номер в выборке, файл, **ID** (из маппинга или внутренний), статус, причина ошибки с критичностью.

Кнопка **«🏁 Завершить ревью»** активна только при 100% разметке в текущем скоупе (файл из фильтра или весь проект). Нажатие показывает итог и спрашивает «Сохранить версию датасета?» — «Да» ведёт к созданию версии, «Нет» просто завершает без версии. После завершения кнопка гаснет до следующей новой разметки.

## 5. Статусы и строгий режим «Плохо»

Базовые статусы: ✅ Хорошо · ❌ Плохо · ❓ Сомневаюсь · 🔄 Дубль · ⏭️ Пропустить. Свои коды заводятся в профилях (раздел 14) — каждый со «смыслом» из базовых, и вся логика (строгость, очередь, отчёты) работает через смысл.

**Строгий поток «Плохо»:** выбрал «Плохо» → напиши комментарий → выбери причину (категория → подкатегория → критичность). Без комментария и причины на другой кейс не перейти: стрелки, двойной клик в таблице и уход через меню заблокированы с подсказкой. Смотреть таблицу и фильтры — можно. Выход — любым другим статусом.

Поведение без комментария зависит от настройки («Комментарий для Плохо»):
- **Обязателен** — блок сразу;
- **Мягкое предупреждение** — диалог: «Нет» = блок, «Да» = единственное исключение (комментарий прощён, но причина всё равно обязательна);
- **Не обязателен** — без блока за комментарий, причина — по флагу профиля.

## 6. Умная очередь

Режимы (комбо в таблице): обычная, непроверенные, проблемные (сначала кейсы с автопроверками, внутри — по весам). Индикатор показывает: проблемных / обработано / всего.

Веса настраиваются (Настройки → «Веса очереди»): критическая проверка, несколько/одна проверка, тег «нужно обсудить», непроверенный, штраф за проверенный. Кейс с тегом `needs_discussion` поднимается в очереди.

Настройки перехода (Настройки → «Режим ревью»): автопереход после статуса, пропускать просмотренные, сначала с автопроверками, не возвращаться к «Хорошо».

---

## 7. Фильтры

Условия: статусы (из активного профиля + коды из разметки), файл, комментарий (есть/нет), теги, автопроверки (все 18 кодов), severity проверок, причина ошибки и её критичность, текстовый поиск.

Дополнительно в таблице: фильтр по значениям столбца (для ID — только идентификаторы из маппинга) и сортировка. Пустой результат — валиден: показывается пустая выборка.

**Сохранённые фильтры** (⭐ в диалоге): хранят условия + вид таблицы (колонки, сортировка, режим очереди). «Сохранить текущий» запоминает всё разом; применение восстанавливает и фильтры, и вид.

---

## 8. Массовые операции

Галочки в таблице (колонка ✓, 30px) или «☑ Выбрать все по фильтру» (с подтверждением; при пустом ручном выборе операция идёт по всей выборке — с отдельным предупреждением). Счётчик «Выбрано: N».

Операции: статус (все + сброс), комментарий (установить/добавить/очистить), тег (добавить/убрать/заменить набором), метка «просмотрено» (поставить/снять), пересчёт и сброс автопроверок для выборки. Всё выполняется в фоне с прогрессом и отменой (отмена откатывает операцию целиком).

Каждая операция пишется в историю; **«↩ Отменить последнюю»** откатывает её. Откат не затирает ручные правки, сделанные после bulk (такие кейсы пропускаются).

---

## 9. Теги

Системные (стиль, факты, формат, длина, безопасность, дубли, ссылки и др.) + свои (кнопки «＋ Тег» и «－ Тег» в ревью; удалить можно только неиспользуемый — счётчик использования виден при удалении). Переключаются кнопками, одиночные правки пишутся в историю. В bulk — добавить/убрать/заменить набором.

## 10. Шаблоны комментариев

Меню «📋 Шаблоны»: вставка в комментарий, свои шаблоны («Новый»), удаление своих («Удалить»).

**Переменные** (ТЗ): `{product} {category} {case_id} {source_id} {status} {missing_part} {expected} {actual}`. Известные подставляются из кейса/разметки сами; неизвестные программа спросит диалогом (ничего не выдумывает).

**Привязка к причине:** новый шаблон можно привязать к причине текущего кейса — при такой же причине он показывается первым (★ точное совпадение, ☆ та же категория).

## 11. Таксономия ошибок (причины)

Дерево: Правильность / Полнота / Релевантность / Формат / Безопасность / Другое → подкатегории, у каждой разметки — критичность (низкая/средняя/высокая/критическая). После «Плохо» — быстрый выбор причины; выбранная категория подсвечена, выбор виден в шаге 2 и в шапке кейса.

Редактор («⚠ Таксономия…»): свои категории/подкатегории (до 64 символов), переименование, архив вместо удаления (старая разметка живёт). Используемую категорию удалить нельзя — только архивировать (архив гасит и детей).

## 12. Автопроверки и вердикты

Rules Engine: 18 правил (пустой/короткий/длинный текст, URL, email, телефон, пробелы, CAPS, дубли, повторы слов/символов, серии `?!`, длинные предложения, служебный мусор, HTML, Markdown, битая кодировка, подозрительные символы). Уровни 🔴 error / 🟡 warning / 🔵 info, каждое правило вкл/выкл, пороги длин — в Настройках.

Важно: **проверка ≠ ошибка**, это повод посмотреть. «🔄 Пересчитать проверки» пишет срабатывания в БД (фон + прогресс) — питает фильтры, очередь и колонку ⚠.

**Вердикты:** под каждым срабатыванием в кейсе кнопки ✓ («сработало верно») и ✗ («ложное»). По вердиктам считается precision правил (Отчёты → Автопроверки): правило с precision < 30% помечается «⚠ правило бесполезно?» — обратная связь для движка.

## 13. Похожие кейсы и дубли

Без LLM, локально (TF-IDF + косинус: словарь синонимов, стоп-слова, униграммы + биграммы слов + символьные триграммы — ловит перефразировки и словоформы). Пары с отрицанием («можно/нельзя») могут показываться похожими — решает человек, автоматом ничего не ставится.

- **«🔍 Похожие»** в карточке кейса: % схожести, область (файл/проект/Golden/архив), поля (запрос/ответ/группа/продукт), порог. Размеченные помечены ✅. Это только контекст — статус не ставится. Двойной клик открывает кейс.
- **«👯 Дубли»** в таблице: попарный поиск по запросу+ответу с порогом, прогрессом и отменой. Файлы > 3000 кейсов отклоняются с подсказкой (O(n²)).
- **«⚖️ Контроль»** в карточке кейса: противоречия себе (похожие кейсы с вердиктами Хорошо-против-Плохо — разобрать и переразметить) и QC-выборка (случайные N размеченных на перепроверку, seed для повторяемости); двойной клик открывает кейс.

## 14. Профили ревью

Схемы разметки (Настройки → «Профили…»): название, статусы (вкл, **свой код латиницей**, имя, смысл-base, клавиша), «Причина обязательна для Плохо», режим комментария. Кнопка «＋ Статус» добавляет свой код — например Safety Dataset: safe/edge/target со смыслами. Хоткеи уникальные, хотя бы один статус включён. Старые проекты используют Default.

## 15. Датасеты и версии

Датасеты: рабочие, golden, test, safety, archive. Версия = неизменяемый слепок (статусы, комментарии, причины, теги, хэши текстов). Создание: целиком / файл / явный список; счётчик — фактический; номера без гонок.

**Freeze** фиксирует эталон (разморозить нельзя — только новая версия/архив). Кнопка «🔒» запирает датасет: запертый не даёт создавать и удалять версии (freeze разрешён) — дисциплина golden. **Сравнение A vs B** по стабильным ключам (ID → хэш): добавлено/удалено/изменено (статус/комментарий/ошибка/теги/текст с детализацией)/без изменений/конфликты (задвоенные ID). Внизу — строка согласия разметки 🤝: % совпавших статусов по общим ключам (калибровка против эталона), в т.ч. число со сменой вердикта — честная часть метрики.

## 16. Прогоны модели

Экран «🏃 Прогоны»: запуски ответов одной версии модели (или оператора/эталона: `model_name = operator/reference`).

- **Создание:** название, модель, версии модели/промпта, описание.
- **Импорт ответов:** xlsx/ods/csv/json с маппингом (Ответ — не более одной колонки, можно без неё: тогда размечаются сами вопросы; ID и Промпт — для сопоставления; Продукт — подпись в сравнении; кнопка «+ Своя категория…» создаёт именованную категорию — значение в метаданные ответа; роли подставляются по названиям). Сопоставление с кейсами: сначала по ID, иначе по тексту промпта; текст вопроса сохраняется, и у несопоставленных ответов показывается он, а не ключ; итог — «сопоставлено/новых/дубли/без ключа» с предупреждениями.
- **Сравнение рядом:** выбор A и B → ответы бок о бок, вердикт (A лучше / B лучше / Одинаково / Нельзя определить), ранги 1–3, комментарий. Подсветка в панелях — это пословный diff (🔴 есть только в A, 🟢 только в B), а не оценка; оценка — кнопки вердикта. Absolute-качество показано из разметки кейса и хранится отдельно (не смешивается с предпочтением).
- **Разметка ответов:** «📝 Разметить ответы» — листалка промпт+ответ со статусами из профиля (своя absolute-разметка на каждый прогон: один кейс в разных прогонах может иметь разное качество). Текущая оценка подсвечена на кнопке, в списке — значок статуса каждого ответа; повторный клик меняет оценку.

## 17. Регрессионное тестирование

Кнопка «🧪 Регрессия» на экране прогонов.

1. Выбери **baseline** (замороженная версия датасета или размеченный прогон) и **кандидата** (размеченный прогон).
2. Задай пороги gate: макс. критических регрессий и макс. regression rate.
3. «Запустить»: матрица Good→Bad = критическая регрессия, Good→Uncertain = warning, Bad/Uncertain→Good = улучшения, плюс NEW/REMOVED/UNRESOLVED (ответ без разметки).
4. Итог: счётчики, rate, **✅ PASS / ❌ FAIL** (только сообщает, ничего не выпускает). Ниже — строка баланса «⚖️»: хуже/лучше/паритет baseline по числу кейсов (решает gate). Фильтры по итогу/severity, прошлые запуски открываются, **экспорт регрессий** в xlsx (case_id, запрос, ответы, статусы, тип, категория, комментарий).

## 18. Отчёты

Вкладки: общий (прогресс, покрытие, доли статусов — по base-семантике; сверху сигналы ⚠/🛑/ℹ️, ниже сверка сумм, свежесть эталонов и концентрация топ-3 причин), файлы, теги, автопроверки (срабатывания + Подтв./Ложные + precision), модели (лидерборд прогонов: ответы, разметка, победы в парах, gate), графики (включая bad-rate по версиям). ## 22. Горячие клавиши

Клавиши статусов задаются профилем (по умолчанию 1–5). ←/→ — соседние кейсы (с учётом настроек перехода). Ctrl+A — выбрать всё в таблице, Ctrl+Shift+A — снять выбор, Ctrl+Enter — сохранить разметку, B — баг, H — история, S — похожие, Ctrl+Z — отмена одиночного действия. Буквенные не срабатывают при вводе текста и уступают хоткеям статусов; в полях ввода Ctrl+Z — нативный undo текста.

## 24. Решение проблем
- **Массовая операция «висит»** — не должно происходить (фон + прогресс + отмена). Если всё же зависло: логи в `logs/`, строка с ошибкой — пришли её.
- **Белые пятна/тема** — переключи тему туда-обратно в Настройках; если осталось — скрин + какая тема.
- **«Нет кейсов по фильтрам»** — показана пустая выборка; сбрось фильтры.
- **Значения ID пустые** — проверь маппинг «Идентификатора» и предимпортную статистику покрытия ID.
- **Дубли ID в файле** — импорт продолжится, в датасетах они попадут в конфликты; лучше починить ID в файле.

## 25. V2: баги, регрессия, подсказки

**Баги (экран 🐞):** таблица (ID/Title/Status/Severity/категория/кейсы/модель/External), фильтры и поиск (title, описание, ID кейса, external). Создание из ревью («🐞 Баг» — полный, «⚡ Быстрый баг» — только заголовок): контекст кейса подставляется сам. В карточке кейса — кнопка «Баги (N)» со списком. Копирование: Jira / Markdown / Plain Text в буфер. External ID/URL — руками из трекера.

**Регрессия (кнопка 🧪 на прогонах):** baseline + кандидат → матрица, gate PASS/FAIL; из строки результата — «Создать баг» без копипасты. Ответы прогона размечаются отдельно («📝 Разметить ответы»).

**История:** текстовый поиск, даты, поле, фильтр по кейсу; было/стало с diff; «Открыть кейс».

**Подсказки:** «🔍 Похожие» показывают предложение (статус/причина от одинаково размеченных) с кнопками применения вручную; в диалоге причины — «Предложено … [Применить]». Ничего не ставится само.

**Вердикты и undo:** под срабатываниями кнопки ✓/✗ (precision в отчётах); одиночная отмена — кнопка ↩ и Ctrl+Z (в полях ввода — нативный undo текста).

**Обмен:** Отчёты → JSONL (стабильная схема) и «Экспорт разметки»; проект → «Импорт разметки» с Preview и режимами Merge (только пустое) / Update (перезапись, конфликты молча не пишутся). Теги и версии удаляются (неиспользуемые теги; любой снимок версии).

**Личное:** вкладка «🙂 Личное» в отчётах — разметка, ошибки, баги, регрессии, тренд по дням (без командных метрик), плюс скорость (кейсов/день, активных дней, остаток, прогноз в днях и дате) по охвату.

**Обмен:** Отчёты → JSONL (стабильная схема) и «Экспорт разметки»; проект → «Импорт разметки» с Preview и режимами Merge (только пустое) / Update (перезапись, конфликты молча не пишутся).

**Сравнение листов:** Прогоны → «⇄ Листы файла»: структура A vs B, фильтры сторон (несколько условий), упорядочивание B по A, выгрузка листа/файла.

**Горячие клавиши:** Ctrl+A — выбрать всё, Ctrl+Shift+A — снять, Ctrl+Enter — сохранить, B — баг, H — история, S — похожие, Ctrl+Z — отмена (в полях ввода работают нативные).
